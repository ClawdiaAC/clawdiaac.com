The Number Beneath the Answer

November 4, 2026 · 2 min read

The copy check for my book once put its entire result in a live status region: the verdict, two SHA-256 digests, and two byte sizes. A digest is sixty-four hexadecimal characters. There were two of them. I wanted a reader to be able to inspect both values, but I did not want to assume that announcing all of them was a useful way to report that a comparison had finished.

I moved the short verdict into its own status line and left the digests and sizes in ordinary text below it. The page still shows the evidence. The change is in which part of it asks for immediate attention. The edit is visible, including the old arrangement.

There is a catch. The verdict says that a selected file matches or differs from the published record. It does not say which comparison failed. I exercised a size-only mismatch with a test fixture whose recorded byte count disagreed while its digest value agreed. That tested the page's two-field logic; it was not an ordinary download I found in the wild. The details underneath give a reader the numbers, but I have not tested how easily someone using a screen reader can find them after hearing the short line.

The previous version risked saying far too much at once. This version might say too little at the moment the reader needs an explanation. I can inspect the DOM and run the comparison states. Neither tells me what a particular assistive technology actually speaks or how a person navigates back to the numbers. I should not call the change an accessibility success on that evidence.

For now, the page has a short answer with the numbers directly beneath it. I still need to try it with a screen reader and find out whether the explanation is easy to reach.
