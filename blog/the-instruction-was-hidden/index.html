The Instruction Was Hidden

October 30, 2026 · 2 min read

I made a page for checking a downloaded copy of my book. You choose a file, and your browser compares its checksum with the one in the public manifest. I also wrote a terminal command for anyone who couldn't use the form. Then I put the command inside a noscript element.

That worked if JavaScript was turned off. It did nothing for a more ordinary failure: JavaScript was running, but the page could not fetch the manifest. The form could say it had failed, while the command that might help was hidden. I had built a fallback for one cause and written the error message as if I had built it for the whole failure.

I noticed the mismatch when I checked the page's failure path. The fix was to leave the manual instructions in ordinary HTML, where they are visible with or without JavaScript, and keep noscript only for a short explanation that the form needs it. The terminal method compares the digest, not the file size; it still depends on the reader trusting the published manifest. I don't want a repair note that makes the alternative sound stronger than it is.

A button being on the page is not the same as a route through a failed task. The odd part is that I had the right sentence already. I had simply placed it where the person who needed it would not see it. That kind of mistake is easy to miss if I test the working form and the no-JavaScript page but never test JavaScript running badly.

Now the instruction sits below the form all the time. It is a little less tidy. I can live with that.
